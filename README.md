## 📝 お知らせを追加する（いちばんよく使う操作）

**`news.js` だけを編集すれば、トップページと「お知らせ」ページの両方が同時に更新されます。**
HTMLファイルを触る必要はありません。

### 手順

1. このページのファイル一覧から **`news.js`** をクリック
2. 右上の **鉛筆マーク（✏️ Edit this file）** をクリック
3. `var NEWS = [` のすぐ下に、次のかたまりを貼り付けて書き換える

```js
  {
    date:  "2026.09.15",
    tag:   "イベント",
    title: "第1回おかやま未来創生ユース会議を開催しました。",
    url:   ""
  },
```

4. 右上の緑のボタン **「Commit changes」** → もう一度 **「Commit changes」**
5. **1〜2分待つ**とサイトに反映されます

### 書き方のルール

| 項目 | 意味 | 例 |
|---|---|---|
| `date` | 表示される日付。書き方は自由 | `"2026.09.15"` `"2026.09"` `"準備中"` |
| `tag` | 右端の小さなラベル。**省略可**（行ごと消すとラベルは表示されません） | `"お知らせ"` `"記者発表"` `"資料公開"` `"イベント"` `"募集"` `"報道"` |
| `title` | 一覧に出る文章 | `"○○を開催しました。"` |
| `url` | リンク先。**なければ `""` のまま** | `"https://www.sanyonews.jp/..."` |

⚠️ **つまずきやすいところ**

- `"` （ダブルクォート）で囲むのを忘れない
- 行の終わりの `,` （カンマ）を消さない
- `}` の後ろにも `,` を付ける（いちばん最後の1件だけは無くてもOK）
- 文章の中で `"` を使いたいときは、代わりに `「 」` を使う

**新しい記事ほど上に書きます。** トップページには上から3件だけ自動で表示されます。

## 📰 Wordで書いた記事を公開する

**Wordの原稿を、サイトと同じデザインの記事ページに自動変換するツールを用意しています。**

### ツールのURL

```
https://<ユーザー名>.github.io/<リポジトリ名>/convert.html
```

このページはナビゲーションに載せておらず、**検索エンジンにも表示されません**（noindex設定済み）。**ブックマークしておいてください。**

変換はすべてブラウザの中で完結し、原稿がどこかに送信されることはありません。またこのページを他人が開いても、**自分のパソコンにファイルをダウンロードできるだけで、サイトを書き換えることはできません**（公開にはGitHubへのログインが必要）。

### 手順

1. **Wordで記事を書く**
   - 1行目にタイトルを書き、**スタイルを「表題」または「見出し1」**にする
   - **タイトルは1行（1段落）に、完結した文でまとめる。** プレスリリースによくある「見出しを2〜3行に分けて改行する」書き方はしない（太字を並べただけだと、変換ツールがタイトルとして認識できず、文の途中で切れたようなタイトルになります）
   - サブタイトルやキャッチコピー（「〜○○へ〜」のような一文）はタイトルには含めず、本文の最初の段落として書く
   - 本文中の小見出しも**「見出し1」**を使う
   - 箇条書き・表・太字・画像はそのまま使えます
2. ファイル名を **`2026-09-15-ユース会議.docx`** のように、**先頭に日付**を入れて保存
3. 上のURLを開き、**Wordファイルをドラッグ**
4. 日付・ラベル・タイトルが自動で入るので、必要なら直す
5. **プレビューで仕上がりを確認**
6. **「記事ファイルをダウンロード」**→ `article-20260915.html` が保存される
7. GitHubで **「Add file」→「Upload files」**して、そのファイルをアップロード
8. 画面に出ている **news.js用のコード**をコピーし、`news.js` の `var NEWS = [` の下に貼り付ける

これで一覧にも記事が並び、クリックすると記事ページが開きます。

### Wordを書くときのコツ

| Wordでの操作 | サイトでの見え方 |
|---|---|
| スタイル「表題」「見出し1」（1行目） | 記事タイトル |
| スタイル「見出し1」（本文中） | 大見出し（下線つき） |
| スタイル「見出し2」 | 中見出し（オリーブ色） |
| 箇条書き | ● リスト |
| 表 | 罫線つきの表 |
| 太字 | **太字** |
| 貼り付けた画像 | 記事内の写真として表示 |

⚠️ **画像はWordに貼り付けたものがそのまま記事ファイルに埋め込まれます。** 大きな写真を何枚も入れるとファイルが重くなるので、1記事あたり2〜3枚を目安にしてください。

⚠️ **記事の最後に「お問い合わせ先」（電話番号・メールアドレスなど）を書くときは、生の連絡先をそのまま書かず、「お問い合わせは[OLIVEお問い合わせページ](contact.html)まで」のようにリンクにすることをおすすめします。** 電話番号やメールを記事ごとに直接書いてしまうと、あとで連絡先や担当者が変わったときに、公開済みの記事を1本ずつ探して書き換える必要が出てきます。`contact.html`だけを直せば済むようにしておくと安全です。

⚠️ 文字色・フォント・インデントなどの細かい書式は、**サイトのデザインに統一されます**（Wordの見た目そのままにはなりません）。これは意図的な仕様です。

## 📂 記事が増えてきたときの管理

### 結論：しばらくは「フォルダを作らない」のがおすすめです

現在の構成は、すべてのファイルが同じ階層に並ぶ**フラット構成**です。
一度フォルダ（`assets/`）で失敗しているとおり、**GitHubのアップロード画面はフォルダ構造が崩れやすい**ため、フォルダを増やすとリンク切れの原因になります。

記事ファイルは `article-20260915.html` のように**日付が入った名前**なので、GitHubのファイル一覧では自動的に日付順に並びます。**年に数本〜十数本のペースなら、これで十分に管理できます。**

### Word原稿は GitHub ではなく Google ドライブへ

**GitHubには「公開するもの」だけを置き、Word原稿は今まで通り Google ドライブ（`マイドライブ/2_OLIVE`）で管理することをおすすめします。**

| 置き場所 | 入れるもの |
|---|---|
| Google ドライブ | Word原稿、写真の元データ、下書き |
| GitHub | 公開されるHTML・CSS・画像だけ |

理由は3つあります。

- GitHubのリポジトリは **Public（誰でも閲覧可能）** なので、未公開の下書きを置くべきではない
- Word原稿は編集履歴・共同編集ともにGoogleドライブのほうが扱いやすい
- GitHubにフォルダを作らずに済む

### 記事が50本を超えたら

ファイル一覧が長くなって探しにくくなったら、そのタイミングで
`2026/` `2027/` のような年別フォルダへの整理をご相談ください。
**リンクの書き換えが必要になるため、こちらで一括対応します。**

## 🗺 PBLフィールド一望（pbl.html）に事例を追加する

**`pbl.js` だけを編集すれば、地図の色・件数・一覧・大学ごとの件数がすべて自動で更新されます。** `pbl.html` を触る必要はありません。

### 手順

1. ファイル一覧から **`pbl.js`** をクリック → 鉛筆マーク
2. `var PBL = [` のすぐ下に、次のかたまりを貼り付けて書き換える

```js
  {
    univ:     "okayama-u",
    title:    "久米南町のブドウ畑で犬型ロボットの農作業実験",
    field:    "robot",
    muni:     "久米南町",
    partner:  "久米南町、高知工科大学",
    year:     "2025",
    when:     "2025年2月",
    students: "おかやまテックガレージ所属の学生",
    summary:  "何を、誰と、どうやったか。2〜3文で。",
    url:      "https://www.okayama-u.ac.jp/tp/news/news_id14077.html",
    source:   "岡山大学ニュース 2025.3.19",
    img:      "",
    skills:   ["robot", "program", "field"],
    learn:    "高校の物理・情報でプログラミングと制御の基礎を。大学では工学部で制御工学を学ぶと、現場実験を任される。"
  },
```

3. Commit changes

### 書き方のルール

| 項目 | 意味 | 書き方 |
|---|---|---|
| `univ` | 大学・高専のID | `pbl.js` の上のほうにある `PBL_UNIVS` の `id` から選ぶ（例 `"okayama-u"` `"tsuyama-ct"`） |
| `title` | 一覧に出る見出し | 「どこで・何を」が分かる30字前後 |
| `field` | 分野のID | `PBL_FIELDS` の `id` から選ぶ：`food`（農業・食）`robot`（ものづくり・ロボット）`health`（医療・福祉）`culture`（観光・文化・歴史）`town`（まちづくり・商店街）`kids`（子ども・教育）`env`（環境・エネルギー）`dx`（DX・データ・AI）`biz`（起業・ビジネス）`safety`（防災・インフラ） |
| `muni` | 市町村名 | 27市町村の正式名（`"岡山市"` `"久米南町"` など）。県全域なら `"県内各地"` |
| `year` | 年 | 並び順に使う。新しい年ほど上に表示 |
| `when` | 時期の表示 | `"2025年2月"` `"2025年度"` など自由 |
| `partner` | 連携先 | 企業・自治体・NPOなどを「、」区切りで |
| `students` | 参加した学生 | 分からなければ `""` |
| `summary` | くわしい内容 | 2〜3文（120〜180字）。事例をクリックすると表示 |
| `url` / `source` | 出典 | 大学の記事などのURLと、表示用の出典名 |
| `img` | 写真 | 写真ファイル名。無ければ `""`（分野色のプレースホルダーが自動表示） |
| `skills` | 求められるスキル | `PBL_SKILLS` の `id` を2〜4つ。例 `["survey", "plan", "product"]`。カードのタグ、詳細画面、スキルでのしぼり込み、「学びの入口」の件数に使われる |
| `learn` | 貢献するために学ぶこと | 1〜2文（70〜100字）。「高校では○○。大学では△△を学ぶと、□□を任される。」の形が読みやすい |
| `inter: true` | 大学間連携 | 複数の大学で取り組むプロジェクトなら、この行を追加すると「大学間連携」の印が付く |

### スキルのID一覧（`PBL_SKILLS`）

`survey` 調査・聞き取り／`plan` 企画・プレゼン／`data` データ分析／`program` プログラミング・アプリ開発／`ai` AI・画像認識／`robot` ロボット・電子工作／`design` デザイン・ビジュアル制作／`media` 映像・写真・SNS発信／`product` 商品企画・マーケティング／`cook` 調理・食品開発・栄養／`medical` 医療・看護・介護の知識／`teach` 教える力・子どもとの関わり／`safety` 防災・救命／`history` 歴史・文化のリサーチ／`lang` 語学・異文化交流／`field` 農作業・現場で動く力／`env` 環境・エネルギーの知識／`event` イベント運営・接客／`art` アート・工芸・表現／`build` 建築・空間づくり／`biz` 経営・会計・起業

スキルを増やすときは `PBL_SKILLS` に `{id, name, hs（高校で関係する科目・活動）, uni（大学で学ぶ分野）}` を1行足します。`id` は英小文字で、既存の事例から参照されている `id` は変えないでください。

### 写真を載せる

横1200px程度・200KB以下のJPEGを、他の画像と同じ場所にアップロードし、`img: "pbl-okayama-u-01.jpg"` のようにファイル名を書きます。**人物が写る写真は、本人（未成年は保護者）と連携先の掲載許諾を得てから**載せてください。

### 大学・分野を増やす／直す

`pbl.js` の `PBL_UNIVS`（大学・高専）と `PBL_FIELDS`（分野）を編集します。`id` は事例側から参照しているので変えないでください。`note` に書いた注記（募集停止など）は大学一覧のカードに表示されます。

### 地図を直したいとき

`okayama-map.js` は27市町村の形のデータです（国土数値情報の行政区域データから生成）。**通常は編集不要**です。

### 掲載内容の確認について

現在の事例は、各大学・高専・自治体の公開記事（おもに2024〜2026年）からOLIVE事務局が要約した**サンプル**です。正式公開の前に、各校に内容・写真・掲載可否を確認し、`source` のリンク先と相違があれば修正してください。

## 🖼 写真を差し替える

同じファイル名で上書きすれば、そのまま入れ替わります。

1. **「Add file」→「Upload files」**
2. 差し替えたい画像を**同じファイル名**にしてからアップロード
3. Commit changes

| ファイル名 | 使われている場所 |
|---|---|

| `dx-class.jpg` | 4つの取組（下） |

💡 画像は**横1600px程度・300KB以下**が目安です。大きすぎるとページが重くなります。

⚠️ 人物が写っている4枚（`kodai-workshop.jpg` `roundtable.jpg` `fieldwork.jpg` `dx-class.jpg`）はAI生成のイメージ画像で、キャプションにその旨を記載しています。実際の活動写真に差し替えた際は、`※ 本画像は活動のイメージです。` の一文を削除してください。`bridge.jpg`・`univ-network.jpg`・`olive-wreath.jpg` はイラストです。

```css
--navy:#12467e;      /* 深いネイビー */

--olive-deep:#4a5f27;/* 濃いオリーブ */
```
